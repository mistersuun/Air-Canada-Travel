# French UI (fr-CA): architecture and conversion guide

Routes ships in English and Canadian French. Two of the ten hubs are in
Quebec (YUL, YQB), so French is Quebec French: "fin de semaine", not
"week-end"; "plaque tournante" for a hub; no space before `?` and `!`, a
no-break space before `:`; « » quotes. Facts-only tone, as in English.

This file is the guide for converting the rest of the app. The pilot (the
shell, Settings and Explore/Home) is the reference: copy its patterns.

## 1. Decision: runtime switching, not `$localize`

We switch language **at runtime**: one build, one service worker, one set of
URLs, a Language control in Settings (Automatic / English / Français), the
default following the device (`navigator.languages`), the choice stored in
prefs (`ac.prefs.v1`, field `language`).

Angular's build-time `$localize` was rejected:

- One build per locale means `/fr/` and `/en/` deploys, a service worker
  (and `ngsw.json`) per locale, Netlify redirects by language, and twice the
  offline cache. An installed PWA is pinned to the scope it was installed
  from, so switching language would mean reinstalling.
- Shared links (`/to/LIS?from=YUL`, `/g/:id#key`, share targets) would need
  a locale prefix, or a redirect that breaks the share-target POST and the
  service worker's navigation fallback.
- Most of our text is built in pure TypeScript (`*-model.ts`, toasts, share
  text), which `$localize` handles only with tagged templates and no
  runtime plural support beyond ICU in templates.

No blocker for the runtime approach was found: everything is signals, so a
locale signal makes every computed and template re-render on a switch. The
French catalogue is a lazy chunk (about 120 kB raw, 30 kB gzipped), fetched
only when French is chosen; English stays in the initial bundle as the
fallback and the source of `MsgKey`. The service worker prefetches it with the
rest of the app (`/*.js`), so switching works offline.

## 2. How it works

| Piece | File | Role |
|---|---|---|
| Locale signal | `src/app/i18n/locale.ts` | `locale()` (signal read), `setLocale()`, `intlLocale()` ('en-US' / 'fr-CA'), device resolution |
| Translator | `src/app/i18n/t.ts` | `t(key, params)`, `tIn(locale, key, params)`, `tOr(key, fallback)`, `isMsgKey`, `formatNumber` |
| Message format | `src/app/i18n/message-format.ts` | ICU subset: `{arg}`, `{n, plural, …}`, `{x, select, …}`, `{n, number}` |
| Catalogues | `src/app/i18n/en/<area>.ts`, `src/app/i18n/fr/<area>.ts` | One file per area; English is the source of truth |
| Data labels | `src/app/i18n/labels.ts` | `regionLabel`, `typeLabel`, `departWindowLabel`, `tripLengthLabel` |
| Service | `src/app/i18n/locale.service.ts` | Preference + device → locale; loads the catalogue, then sets the locale and `<html lang>`; follows `languagechange` and other tabs; `ready` for the app initializer |
| Titles | `src/app/i18n/title-strategy.ts` | `document.title` in the UI language; re-applied on a switch |
| Settings | `src/app/components/settings/settings.component.ts` | Language control (`data-setting="language"`) |

**How locale reaches pure functions.** `locale` is one module-level signal.
`t()` reads it, so any function that calls `t()` (or a formatter) is pure
given the locale, and any `computed()` or template that calls it tracks the
locale and re-runs on a switch. No translator needs to be threaded through
model functions; specs call `setLocale('fr')` (`src/test-setup.ts` loads the
French catalogue up front and resets to English after every test).
`LocaleService` is created by the app initializer, which waits for its
`ready` (the French chunk, or English after a 3 s budget) before the first
render, and by `AppComponent`. While a catalogue loads, the previous language
stays on screen; `loadCatalogue()` in `t.ts` does the fetch.

**Typed keys.** `MsgKey` is `keyof` the merged English catalogue, so a typo is
a `tsc` error. Each French area file is typed `Translation<typeof en>`, so a
missing or extra French key is a `tsc` error too.

**Per-area files.** Every area is already registered in `en/index.ts` and
`fr/index.ts`; a conversion only fills its own two files and never touches the
indexes. Keys always start with the area name (`home.where`,
`trips.detail.rename`); `i18n.spec.ts` enforces this, which also rules out
collisions between areas.

Shared areas, already filled (add to them sparingly, and only keys that are
truly generic; coordinate in the PR description):

- `common`: Retry, Done, Close, Skip, Next, Reset, Clear, Open, Copied,
  Couldn't share, Show less, See all, Star/Unstar {code}.
- `format`: everything `ui/format.ts` and `utils/time.ts` print.
- `data`: display names of data identifiers (regions, trip types, departure
  windows, trip lengths, hub names, weekday letters).

## 3. French conventions (decided)

| Topic | English | French | Notes |
|---|---|---|---|
| Clock, 24h (default) | `21:05` | `21:05` | OQLF writes "21 h 05" in prose but accepts `21:05` in tables and timetables; departure boards and boarding passes use it, and it fits the compact rows. `formatClock` keeps it in both languages. |
| Clock, 12h | `9:05 PM` | `9:05 p.m.` | |
| Short date | `Wed, Oct 14` | `mer. 14 oct.` | `formatKey(key, opts)` uses the UI language by default |
| Long date | `Wednesday, October 14` | `mercredi 14 octobre` | `longDay` |
| Week range | `Oct 12 – 18` | `12–18 oct.` | `weekRangeLabel` |
| Duration (compact) | `6h35`, `45m` | `6 h 35`, `45 min` | `hm`; no-break spaces |
| Duration (spaced) | `2h 10m`, `3d 22h` | `2 h 10 min`, `3 j 22 h` | `countdown`, `formatStay`, `formatDuration` |
| Weekdays | `Mon` / `M` | `lun.` / `L` | `weekdayShort(i)`, `weekdayLong(i)`, `weekdayLetters()` — never `WEEKDAY_SHORT` for display |
| Months | `Nov` | `nov.` | `monthShort(i)` |
| Numbers | `1,234` | `1 234` | `{n, number}` in a message, or `formatNumber(n)` |
| Quotes | “Lisbon” | « Lisbon » | |
| Colon | `Sort: A–Z` | `Tri : A–Z` | write ` ` before `:` in French |
| `?` `!` `;` | — | no space before | Quebec usage |
| Apostrophe | | `'` straight | plain text in messages (no ICU quoting) |

Write no-break spaces as ` ` escapes in catalogue files, never as raw
characters (invisible in review). Intl output also contains no-break spaces
(U+00A0, U+202F); specs that compare French dates should normalise them.

Style: buttons and menu items use the infinitive (« Choisir une date de
départ », « Ajouter un vol de rechange »); sentences that tell the reader what
to do use the imperative (« Choisissez un jour… »). French sentence case
everywhere, also in titles. Dates after a verb or noun take « le »
(« Début le {date} », « Parti le {date} »). Durations: « 6 h 35 »,
« 25 min » with no-break spaces. "x of n" is « x sur n ». A count that only
appears as `{n}` (no plural branch) goes after a label (« Enregistrées : {n} »)
rather than before an agreeing participle.

Keep "Air Canada", "Routes" (the app name), airport codes, flight numbers and
city names as they are. City and country names come from data and stay in
English for now (see §8).

## 4. Converting a component or model file

1. **Read the pilot.** `pages/home/home.page.ts` (template + computeds),
   `pages/home/home-model.ts` (pure functions), `pages/home/results-list.component.ts`
   (select), `pages/home/filters/*` (labels for data), `shell/onboarding-sheet.component.ts`
   (options built from keys).
2. **Add the English keys** to your area's `src/app/i18n/en/<area>.ts`,
   grouped by component, with the exact English text the UI has today
   (specs that assert English text keep passing).
3. **Add the French** to `src/app/i18n/fr/<area>.ts`. `tsc` tells you what is
   missing.
4. **Replace the strings:**
   - Template text: `{{ t('home.where') }}` with `protected readonly t = t;`
     on the component (import from `i18n/t`). If the template already uses
     `t` as a loop or `as` variable, rename that variable (see
     `shell/tab-bar.component.ts`, `app.component.ts`).
   - Static attributes become bindings: `aria-label="Close"` →
     `[attr.aria-label]="t('common.close')"`; component inputs
     `title="Settings"` → `[title]="t('settings.title')"`, `ariaLabel="…"` →
     `[ariaLabel]="t('…')"`.
   - Strings built in code: `t('key', { param })`. Never concatenate
     translated fragments into a sentence; one message per sentence, with
     parameters (word order differs in French).
   - Constant arrays of labels (`TABS`, `SORT_OPTIONS`, `SegOption[]`): store
     **keys** (`label: MsgKey`) and translate where shown, or turn the field
     into a `computed()` that maps keys to `t()` (so it follows a switch).
     A plain class field built with `t()` runs once and goes stale.
   - Signals that hold a message (`msg = signal<string>()`): hold the
     `MsgKey` (plus params) instead and translate in the template, as in
     `components/settings/settings-background.component.ts`.
   - Toasts (`state.flash(t('…'))`): translate at call time; a toast is
     short-lived, so it need not follow a switch.
5. **Pure model functions** (`*-model.ts`) call `t()` directly; no signature
   change. They stay testable: specs call `setLocale()`. Do not cache built
   text in module-level maps unless the cache key includes `locale()` (see
   `utils/season.ts`).
6. **Plurals**: `'{n, plural, one {# try} other {# tries}}'` /
   `'{n, plural, one {# essai} other {# essais}}'`. French "one" covers 0 and
   1 ("0 essai"); use `=0 {…}` for a special zero. Never write
   `n === 1 ? 'x' : 'xs'` in code.
7. **Variants of a sentence** (day vs week, kind of event): one message with
   `{span, select, day {…} other {…}}` instead of splicing "this date" into
   a sentence — French needs agreement ("cette date", "cette semaine").
8. **Dates and times**: use `formatKey(key, opts)` (follows the UI language),
   `shortDay`, `longDay`, `weekRangeLabel`, `formatClock`, `hm`,
   `weekdayShort/Long/Letters`, `monthShort`. Never hard-code month or
   weekday names, `'en-US'`, or `toLocaleDateString()` without a tag.
9. **Data identifiers** (regions, trip types, departure windows, trip
   lengths, sort keys) stay English in data, URLs, storage and logic; show
   them with `regionLabel(r)` etc. Never compare against translated text.
10. **Text that leaves the device** (share text, calendar files, copied
    links' text, notifications): use `t()` too, so it is in the language the
    user reads. Do not translate anything that is parsed back
    (`.ics` field names, URL parameters, storage keys, `data-*` hooks).
11. **Route titles**: a static `title` in `app.routes.ts` is a key
    (`'shell.title.map'`); a resolver returns `t('shell.title.page', { page })`.
    They live in the `shell` area; ask in your PR if you need a new one.
12. **Specs**: existing English assertions should keep passing unchanged. Add
    at least one French assertion per converted component or model (call
    `setLocale('fr')`, reset in `afterEach`). Prefer data hooks
    (`data-*`) over text in new specs.
13. **Tick your paths** in the converted list (§6) and run the guard.
14. Run: `node_modules/.bin/vitest run src/app/i18n <your dirs>`,
    `npx tsc --noEmit -p tsconfig.app.json`, `npx ng build --output-path <scratch>`
    (templates are only type-checked by the build).

## 5. The guard

`src/app/i18n/guard.spec.ts` runs with the normal test suite. For every path
ticked `[x]` below it flags:

- template text, and static `aria-label`, `title`, `placeholder`, `alt`,
  `ariaLabel`, `aria-valuetext` values containing words;
- TypeScript string literals that read like English prose (two words or more),
  outside `t()`/`tIn()`/`tOr()` arguments, imports, `styles`, `selector`,
  `host` and `new …Error(…)` messages.

A line ending in `// i18n-ignore` is skipped: use it for identifiers, data and
log text, never for UI text. "Routes" (the brand) is allowed in templates.
Single English words in TypeScript (`'Retry'`) are not caught; review for them.

Run it alone: `node_modules/.bin/vitest run src/app/i18n/guard.spec.ts`.
The catalogue checks (`src/app/i18n/i18n.spec.ts`) fail on an empty French
value, a French value identical to the English one (unless listed in
`SAME_IN_FRENCH` there), and arguments that differ between languages.

## 6. Converted list (read by the guard)

Tick a path (`- [ ] ` → `- [x] `) when every file under it is converted. A
path is a directory (recursive, `testing/` skipped) or a file. Each chunk has
its own block, so parallel edits do not touch the same lines.

Shared format keys already exist for common phrases; reuse them rather than adding duplicates: `format.stops` ("1 stop · YYZ"), `format.todayLower`, `format.yesterdayLower`, `format.daysAgo`, `format.daily`, `format.nonstop`, `format.via`.

The guard also scans string literals inside `{{ }}` and `[binding]="…"` expressions. French catalogue values must use a no-break space (U+00A0) before ":" and inside « », and none before ? ! ; (enforced by i18n.spec.ts).

## 7. Chunk plan (4 parallel workers)

Balanced by the number of UI strings (~300 each, measured by a scan of
quoted English phrases) and chosen so no two chunks edit the same file.
Each chunk owns the catalogue files listed; all are already created and
registered in both indexes.

## 8. Not covered yet

- `src/index.html` and `public/manifest.webmanifest` are English (`<html
  lang="en">` is corrected at startup; the pre-paint script is CSP-hashed,
  so it was left alone).
- City and country names come from data in English. A later step can show
  countries with `Intl.DisplayNames` (needs ISO codes in the data) and add
  French city names where they differ (Londres, Lisbonne, Athènes).
- Time-zone abbreviations (`tzAbbr`) stay English (EST, not HNE).
- Netlify functions return English errors; the app should map them to keys.
